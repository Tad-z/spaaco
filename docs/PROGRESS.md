## Phase 0: Contract and mocks

- **0.1 Scaffold the TypeScript repo** — package.json (ESM, Node ≥ 24, every CLAUDE.md script), strict tsconfig + build config, Vitest, Prettier, and an ESLint flat config whose `import/no-restricted-paths` zones implement the ARCHITECTURE.md layer table. The boundary rule is covered by `tests/unit/layer-boundaries.test.ts`, which lints a throwaway controller→model import and asserts it errors, so the rule can't silently stop matching. Notable: the rule needs `eslint-import-resolver-typescript`, because NodeNext imports are written `.js` while the file on disk is `.ts` — without it the zones match nothing and pass vacuously. sharp pinned to ≥ 0.35.4 (0.33 carries high-severity libvips advisories); `npm audit` is clean.
- **0.2 OpenAPI spec for the public API** — `openapi/openapi.yaml` (3.1) covering all 17 public operations, with 77 reusable component schemas, shared parameters and error responses; `npm run types:gen` emits `src/types/api.generated.ts` and `src/types/api.ts` aliases every schema. `npm run types:check` fails the build when the generated types drift from the spec. Notable: response examples are `$ref`s into `fixtures/responses/`, which Prism resolves but Redocly's `no-invalid-media-type-examples` cannot (it validates the literal `{$ref}` node), so that one rule is off and fixture/schema validation is done with ajv in the contract tests instead. Response fixtures landed in this commit because the spec cannot lint without them.
- **0.3 Fixtures from SEED_CONTENT.md** — 23 response fixtures in `fixtures/responses/` and 9 raw collection documents in `fixtures/seed/` (settings, practice areas, people, offices, recognitions, faqs, insights, jobs, pages), all transcribed from `docs/SEED_CONTENT.md` with `[PENDING FROM FIRM]` wherever the designs show nothing. Seed documents reference other collections by slug and carry image *placeholder descriptors* rather than URLs, so `npm run seed` (2.4) can mint Media records while the launch loader (7.5) can skip them. `tests/contract/fixtures.test.ts` validates all 23 against their spec schemas with ajv, and fails on an orphaned or missing fixture; verified it bites by corrupting a fixture's type and adding a stray field. The documented design conflicts (partner titles, the 15+ Areas stat, the identical NYSC job, the footer office order) are seeded as designed, per DECISIONS.
- **0.4 Mock server + frontend handoff** — `npm run mock` serves the spec on :4010; `curl localhost:4010/api/v1/pages/home` returns the home fixture byte-for-byte. Required moving the `/api/v1` prefix from `servers` into the spec's path keys, because Prism ignores a server base path and has no flag for it (ADR-019). `docs/FRONTEND_HANDOFF.md` documents the mock, the conventions, every endpoint, all 17 known placeholders and the not-yet-designed screens. Two mock limitations are called out there: `/pages/{key}` always serves the `home` example unless the request sends `Prefer: example=<key>` (Prism cannot select an example by path parameter), and query filters are validated but don't change the payload.

### Phase 0 review (api-reviewer)

- **Phase 0 review fixes** — the api-reviewer returned "changes required" with 5 majors and 14 smaller findings; all 5 majors and 10 of the rest are fixed (ADR-022 … ADR-028). Contract changes: `role` became a documented group filter so the Partners tab keeps the Managing Partner; `seo` was removed from `PersonDetail`/`InsightDetail` and narrowed to `SeoBasic` on `PracticeAreaDetail`, matching DATA_MODEL; `home.aboutFirm.image` was deleted as a frontend asset (ADR-012); `Image.focalPoint` became required; `FILE_REJECTED` (422) was added. Tooling: the middlewares ESLint zone no longer quietly allowed `cache.service.ts`, `models → helpers` is now permitted and documented (ADR-022), and `validators`/`config` gained the zones they were missing. Tests: `fixtures.test.ts` now validates inline and request-body examples too (verified it bites), and `coverage.test.ts` is the tripwire for 7.6. Finding 15 (the fixture count) was wrong and is not a fix: there are 23 response fixtures, all referenced. Two findings were accepted rather than fixed, with reasons: the demo insight duplicates keep the `insights.list.json` filename (it is the canonical example for that operation) and are explained in the handoff instead; and the video insight keeps `videoUrl: "[PENDING FROM FIRM]"` so the seeded page still matches its fixture for task 3.6. One finding cannot be fixed: the scaffold commit swept in `openapi.yaml` and the fixtures, so the 0.2 and 0.3 commit messages describe work already committed — history is not being rewritten, and tasks are one-per-commit from 1.1 on.

## Phase 1: Foundation

- **1.1 Config + logger + errors** — `config/env.ts` is the only reader of `process.env` (ESLint-enforced); it exports `parseEnv(source)` alongside the frozen `config`, so tests exercise both paths without mutating the real environment. Failures report *every* bad variable at once, and two checks go beyond plain schema validation: selecting a driver without its credentials fails at boot rather than on the first request that needs it, and production refuses the `.env.example` placeholder secrets by value. `core/errors.ts` has one `AppError` subclass per spec error code, and its `toResponse()` bodies are validated against the spec's own `ErrorResponse` schema with ajv, so an error body that drifts from the contract fails a test. `core/logger.ts` redacts `req.body` wholesale rather than listing personal fields, so a new form field cannot leak on the day it is added. 72 new tests. Notable: `tests/support/setup-env.ts` runs via vitest `setupFiles` because config parses at import time.
